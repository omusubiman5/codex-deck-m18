# macOS版VSD Craftブリッジ統合 実装報告書 V1

2026-10-01

## 1. 実施内容

[実装計画書V1](実装計画書V1.md)に沿って、macOS版VSD CraftでもWindows版と同じブリッジ統合（VSD Craft起動時のCodex自動起動・接続・設定画面からの復旧）を実装した。

### 変更ファイル

- `launcher/macos/codex-deck-macos.ts`
  - `inspect`コマンドを追加。`{"state":"stopped|connectable|restart-required","version":"..."}`をstdoutへJSON出力する。Windows版`Start-CodexDeck.ps1 -Inspect`と同じ契約。状態判定は`bridgeInspectionFor`としてexportし、単体テスト対象にした。
  - `connect`コマンドを追加（対話的復旧）。`bridge-recovery.lock`（既存`acquirePidLock`のPIDディレクトリ型）でsingle-flight化し、取得失敗時は0終了。`restart-required`時のみ`osascript`の確認ダイアログを表示し、既定・キャンセルボタンは「キャンセル」側。承認時は`startOnce(true)`でSIGTERMによるgraceful再起動（force killなし）。非0終了は`CANCELLED`を出力して0終了し、Codexを変更しない。
  - `start`/`connect`の実行経路に`bridge-launch.lock`を追加し、プラグイン・手動・watcher経由の重複起動・重複接続を直列化。`inspect`/`dry-run`/`self-test`はロック対象外（Windows版と同じ）。
- `src/vsd-bridge-manager.ts`
  - `createVsdBridgeManager`にdarwin分岐を追加。`vsd-bridge-managed.json`と`launcher/codex-deck-macos.mjs`が揃う場合のみ、VSD Craft同梱node(`process.execPath`)で`inspect`/`start`/`connect`を呼び出す依存を生成する。`VsdBridgeManager`クラス本体とPIメッセージ仕様は変更なし。win32分岐は共通の`parseInspectionState`へ整理しただけで動作は同一。
  - テスト用に`{ platform, root }`の注入引数を追加（既定は現行動作）。
- `scripts/build-vsd-craft.mjs`：`release/codex-deck-launcher-macos/codex-deck-macos.mjs`をパッケージ`launcher/`へ同梱。
- `scripts/validate-vsd-craft.mjs`：同梱必須ファイルへ`launcher/codex-deck-macos.mjs`を追加。
- `scripts/package-vsd-craft-installers.mjs`：mac ZIPの`verifyArchive`必須リストへ`launcher/codex-deck-macos.mjs`を追加。
- `test/macos-launcher.test.ts`：inspect状態契約、connect/inspectコマンド、両ロック、osascript確認経路、キャンセル既定、force kill不在を確認するテストを追加。
- `test/vsd-bridge-manager.test.ts`：darwin factoryがマーカー・ランタイム両方を要求すること、linuxでは生成されないことを確認するテストを追加。
- `test/vsd-craft-macos.test.ts`：macOSランタイム同梱の静的検証を追加。
- `README.md`：macOS導入節に「起動と接続の復旧」を追加。
- `docs/vsd-craft/MACOS.md`：接続経路の記述をブリッジマネージャー＋観測watcherへ更新し、検証手順に起動・復旧項目を追加。
- `docs/ARCHITECTURE.md`：ブリッジ統合を両プラットフォームの記述へ更新し、macOS側の`inspect`/`start`/`connect`・osascript確認・PIDロック・SIGTERM-only再起動を記載。

## 3. 実機未検証の項目

Codex Desktop・VSD Craft macOS版・M18実機が揃う環境での確認は未実施。以下は実機で要確認:

- VSD Craft起動→Codex未起動時の自動起動（初回1回のみ）→Agentキー表示
- 通常起動済みCodexで`restart-required`表示→「接続・復旧」→osascript確認ダイアログ→承認でgraceful再起動→接続
- ダイアログのキャンセルでCodexを変更しないこと
- Codexを閉じた後の再自動起動がないこと
- 下段3ボタンのシーン切替と45操作配置の回帰

`docs/vsd-craft/MACOS.md`の方針に従い、これらが終わるまでmacOS対応を「実機検証済み」とは扱わない。

## 4. 残リスク

- VSD Craft macOS版のプラグインホスト(node20/CodePathMac)の挙動がWindows版と異なる場合、マネージャーの子プロセス呼び出しやPI通信に差異が出る可能性。実機で確認する。
- `osascript`確認ダイアログはGUIセッション前提。権限不許可・非GUI環境ではキャンセル扱い（fail-safe側）となる。
- 将来のCodex更新で`open -a`の引数扱いが変わる可能性。既存`buildCodexLaunchSpec`の範囲で追従する。
