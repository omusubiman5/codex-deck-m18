# macOS版VSD Craftブリッジ統合 実装計画書 V1

## 1. 目的

macOS版VSD Craftでも、Windows版で実装済みの「VSD Craftの起動でCodexブリッジが使える」統合起動を実現する。

- VSD Craft(macOS)起動時、Codexが未起動ならプラグインがloopback CDP付きで自動起動する。自動起動はプラグイン開始時の1回のみ。
- 接続可能なCodexセッションは再起動せず再利用する。
- 接続口のない通常起動済みCodexは自動再起動しない。VSD Craftのボタン設定画面の **Codex 接続 → 接続・復旧** から、確認ダイアログを経てユーザーが再起動を選べる。
- ユーザーがCodexを閉じた後に繰り返し起動しない。
- 切断中の使用量・リセット残数は「未接続」と表示する（既存の共通化済みロジックをそのまま使用）。

## 3. 実装対象

1. `launcher/macos/codex-deck-macos.ts`に`inspect`コマンドを追加する。`{"state":"stopped|connectable|restart-required","version":"..."}`をstdoutのJSONのみで出力する。判定はWindows契約と同じ: 正常なloopbackポート検出→`connectable`、メインプロセスあり・ポートなし→`restart-required`、プロセスなし→`stopped`。状態計算はexport関数化して単体テスト可能にする。
2. 同ファイルに`connect`コマンドを追加する(対話的復旧、`Connect-VSDCraftBridge.ps1`のmacOS対等物)。
   - PIDディレクトリロックでsingle-flight化し、取得失敗時は0終了する。
   - `inspect`で`restart-required`の場合だけ`osascript`の確認ダイアログを出す。既定ボタンはキャンセル側とし、非0終了(キャンセル・実行不可)は`CANCELLED`を出力して0終了、Codexを変更しない。
   - 承認時は`startOnce(true)`でSIGTERM graceful終了後にCDP付き再起動。force killはしない。
   - `connectable`/`stopped`時は`startOnce(false)`を実行する。
3. `start`/`connect`の実行経路に起動用PIDロック(`bridge-launch.lock`)を追加し、プラグイン・手動実行・watcher経由の重複起動・重複接続を直列化する。`inspect`/`dry-run`/`self-test`はロックしない(Windows版もInspect/DryRunはmutex対象外)。
4. `src/vsd-bridge-manager.ts`にdarwin分岐を追加する。
   - `vsd-bridge-managed.json`と`launcher/codex-deck-macos.mjs`の双方が存在する場合だけマネージャーを生成する。
   - 依存実装は`execFile(process.execPath, [<plugin>/launcher/codex-deck-macos.mjs, ...])`で、`inspect`→`inspect`、`connect(false)`→`start`、`connect(true)`→`connect`を呼ぶ。timeoutは非対話60秒・対話無制限でWindowsと同じ。
   - `VsdBridgeManager`クラス本体・状態機械・PIメッセージ仕様は変更しない(依存注入で両OS共有)。
   - win32分岐とその他OSの`undefined`返却は変更しない。
5. `scripts/build-vsd-craft.mjs`：`release/codex-deck-launcher-macos/codex-deck-macos.mjs`をパッケージ`launcher/`へ追加コピーする。単一パッケージが両OS対応になる(CodePathWin/CodePathMacと同じ考え方)。
6. `scripts/validate-vsd-craft.mjs`：同梱必須ファイルに`launcher/codex-deck-macos.mjs`を追加する。
7. `scripts/package-vsd-craft-installers.mjs`：mac ZIPの`verifyArchive`必須リストへプラグイン内`launcher/codex-deck-macos.mjs`を追加する。
8. 文書更新：`README.md`のmacOS導入節に「起動と接続の復旧」を追記、`docs/vsd-craft/MACOS.md`の検証手順を更新、`docs/ARCHITECTURE.md`の`Non-VSD and macOS startup behavior is unchanged`の記述を現状へ更新。
9. テスト追加(第8章)。

## 4. 非対象

- M18直接接続(フルOSS構成)のmacOS移植。Rust adapterのmacOSビルド、`Start-CodexDeck-M18.ps1`/`Watch-CodexDeck-M18.ps1`のzsh化、常駐化は別計画とする。
- 会議パネル(Windows専用)のmacOS対応。
- VSD Craft本体、Codex Desktop、M18ファームウェア、USBドライバーの変更。
- LaunchAgent watcherのpolicy変更(observation-onlyを維持)。新しい常駐物も増やさない。
- Windows版で実施した旧経路撤去相当のmigration。macOSには旧ランチャー・直接接続ランタイム・ショートカットが存在しないため不要。
- iPhone companion、multi-host relay、Nearby pairingの仕様変更。
- Codexの強制終了(force kill)。macOSでは従来通りSIGTERMのみとする。

## 5. 設計

### 5.1 macOS側コマンド

- `inspect`：既存の`discoverCodexInstallation`＋`findMainProcess`＋`healthyDebugPort`を再利用して状態を計算し、`{"state","version"}`のJSONのみをstdoutへ出力する。`dry-run`の人間向け出力とは分離する。
- `connect`：`~/Library/Application Support/CodexDeck/bridge-recovery.lock`(PIDディレクトリ、`acquirePidLock`流用)を取得し、失敗時は何もせず0終了する(Windowsの`CodexDeckInteractiveRecovery` mutex相当)。
  - `restart-required`のみ確認ダイアログを表示：`osascript -e 'display dialog "<警告文>" with title "VSD Craft — Codexの接続を復旧" buttons {"キャンセル","再起動して接続"} default button "キャンセル" cancel button "キャンセル" with icon caution'`。警告文はWindows版と同等の内容(全ウィンドウが閉じ作業が中断される旨)を使う。
  - 非0終了はキャンセル・GUI不可を含め`CANCELLED`扱いで0終了し、Codexを変更しない(fail-safe側へ倒す)。
- `start`/`connect`共通の起動直列化：`bridge-launch.lock`を`acquirePidLock`で取得し、取得失敗時は`start`がエラー終了・`connect`が0終了する(Windows mutexの`WaitOne(0)`と同等の意味付け)。

### 5.2 プラグイン側

- `createVsdBridgeManager`をdarwin対応にし、依存注入は既存`BridgeDependencies`のまま使う。macOSのマネージャーは`launcher/codex-deck-macos.mjs`をVSD Craft同梱node(`process.execPath`)で呼ぶため、ユーザー側のNode.js導入は不要(Windowsで`-NodePath process.execPath`を渡す設計と同じ効果)。
- `startWindowsBridgeSupervisor`はWindows専用のまま変更しない。macOSではインストール時のLaunchAgent watcherが観測・relay・bridge再有効化を担うため、supervisor相当の新設はしない(Windowsとの設計差異として明示)。
- マネージャーの`connect`は`startOnce`→`enableBridge`まで同期的に完結する。watcherが同一世代のbridgeへ再度`enableBridge`を適用する場合があるが、冪等でありWindows版と同じ多重適用パターン。

### 5.3 パッケージ・配布

- プラグイン同梱の`launcher/codex-deck-macos.mjs`が正規の実行物。インストーラが配置する`~/Library/Application Support/CodexDeck/launcher-macos`は手動起動・LaunchAgent用として残し、役割が競合しない。
- mac ZIPの構成変更はプラグイン内1ファイル追加のみ。`Install Codex Deck.command`と`launcher-macos/`同梱物は変更不要。
- 既存のmacOS導入済み環境はプラグインとLaunchAgentが残るため、新パッケージの適用だけで統合機能が有効になる想定。

## 7. 互換性

- Windows経路は一切変更しない(win32分岐、PowerShell群、manifest、配布物)。
- macOSの既存`start`/`dry-run`/`install`/`uninstall`/`watch`動作と`~/Library/Application Support/CodexDeck`のファイル配置を維持する。
- PIの`vsd-bridge`メッセージ仕様は変更なし。
- `inspect`のJSON契約`{"state","version"}`はWindowsの`-Inspect`出力と同形にする。

## 8. テスト

### 8.1 自動テスト

- `inspect`：stopped/connectable/restart-requiredの3状態とJSON契約。
- `connect`：`restart-required`時のosascript確認経路、キャンセル時に`startOnce`を呼ばないこと、承認時に`startOnce(true)`へ進むこと、ロック重複で0終了すること。
- マネージャー：darwin依存でtick→`inspect`、初回autoStart→`start`、recover→`connect`が選ばれること。`VsdBridgeManager`の既存テストは依存注入済みのためクラスを流用する。
- パッケージ：`launcher/codex-deck-macos.mjs`同梱とmanifest検証。
- 回帰：`npm run check`、`npm test`、`npm run validate:vsd-craft`、`npm run package:vsd-craft-installers`。

### 8.2 実機(macOS + VSD Craft + M18)

- VSD Craft起動→Codex未起動時の自動起動(初回1回のみ)→Agentキーの状態表示。
- 通常起動済みCodexで`restart-required`表示→「接続・復旧」→確認ダイアログ→承認でgraceful再起動→接続。
- ダイアログのキャンセルでCodexを変更しない。
- ユーザーがCodexを閉じた後に再自動起動しないこと。
- 下段3ボタンのシーン切替と45操作配置の回帰。
- 実機とM18を接続した最終確認が終わるまでは、macOS対応を「実機検証済み」とは扱わない(`docs/vsd-craft/MACOS.md`の方針を踏襲)。

## 9. 完了条件

- macOS版VSD Craftで、Windows版と同じ起動・接続・復旧導線が動作する。
- 実行中Codexの自動再起動が一切なく、再起動は確認ダイアログ経由のみである。
- 二重起動・二重接続がロックで防がれる。
- 全自動テスト・型検査・VSD Craftビルドと配布物検証が合格する。
- 実機検証結果を実装報告書へ記録し、未検証項目を明示する。

## 10. ロールバック

- 変更は`codex-deck-macos.ts`への新規コマンド追加、プラグイン分岐、パッケージ同梱が中心。新コマンドとdarwin分岐を外せば旧動作へ完全復帰できる。
- 配布物はプラグイン内ファイル追加のみで、旧mac ZIPの構成を壊さない。
- LaunchAgent、`watcher-state.json`、`host.json`等の既存状態ファイルは変更しないためmigrationは不要。

## 11. リスク

- VSD Craft macOS版のプラグインホスト(node20/CodePathMac)がWindows版と異なる挙動をする可能性がある。実機での要確認項目とする。
- `osascript`確認ダイアログはGUIセッション前提。権限不許可・非GUI環境ではキャンセル扱いへ倒す(fail-safe側)。
- `open -n -a`による起動が、将来のCodex更新で引数の扱いを変える可能性がある。既存`buildCodexLaunchSpec`の範囲で追従する。
- SIGTERM graceful終了は強制終了より遅い。15秒timeout超過時はエラーを返し、force killはしない(現行仕様を維持)。
- プラグイン内`launcher/codex-deck-macos.mjs`とインストーラ配置の`launcher-macos`が二重に存在する。バージョン差異時はパッケージ同梱版を正とする。
