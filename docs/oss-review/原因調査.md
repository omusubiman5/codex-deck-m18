# OSS選択・配布物レビュー 原因調査

調査日: 2026-08-16

## 1. 対象事象

添付レビューで、次の問題が指摘された。

1. バンドル済みプラグインに`LICENSE`と第三者ライセンス通知がない
2. フォーク後も`package.json`が上流プロジェクトの名前・著者・URLを示している
3. READMEがVSD Craft必須経路とフルOSS経路の性質を説明していない
4. CIがVSD Craft成果物とRust M18アダプターを検証していない
5. `com.simeo.codex-deck`の識別子を継続利用する権限・互換性方針が不明確
6. `dist/m18`のGPLアダプターバイナリとMITバンドルにライセンス文書が同梱されない

## 2. 確認した事実

### 2.1 配布ライセンス

- `scripts/build.mjs`はesbuildの`bundle: true`で`bin/plugin.mjs`を生成する。
- 修正前のビルド処理は実行コード、manifest、画像、Property Inspectorだけをコピーしていた。
- 修正前の`dist-vsd-craft/com.simeo.codex-deck.sdPlugin`直下には`LICENSE`も`THIRD_PARTY_NOTICES.md`もなかった。
- `scripts/audit-release.mjs`は秘密情報・私的状態・禁止画像を検査していたが、ライセンスファイルを監査条件に含めていなかった。

### 2.2 プロジェクト識別

- Git remoteは`https://github.com/omusubiman5/codex-deck-m18.git`である。
- 修正前の`package.json`は`codex-stream-deck`、`Dazer`、上流URLを記載し、`private: false`だった。
- ルート`LICENSE`は上流の`Copyright (c) 2026 Dazer`だけだった。

### 2.3 OSS経路の説明

- VSD Craft経路はメーカー製のプロプライエタリアプリを実行時に必要とする。
- M18直接接続はMITのNode.js部分、GPL-3.0-onlyのRustアダプター、MPL-2.0のmirajazzで構成される。
- READMEは前者を「推奨」、後者を「旧方式・ロールバック用」と表示し、依存とライセンス上の違いを選択表に示していなかった。
- RustアダプターとNode.jsは別プロセスで、JSON Lines/stdioだけを境界にしているが、その設計意図がREADMEに書かれていなかった。

### 2.4 CI

- 修正前のCIはNode.js 24だけで`check`、`test`、Elgato向け`validate`を実行していた。
- VSD Craftが使用するNode.js 20、`validate:vsd-craft`、`cargo build`、生成後のライセンス監査はCI対象外だった。

### 2.5 M18配布物（検収追補）

- `scripts/build-m18.mjs`はNode.js側を`bundle: true`で`codex-deck-m18.mjs`へまとめる。
- 同じ`dist/m18`へGPL-3.0-onlyの`codex-deck-m18-adapter.exe`をコピーする。
- 修正前はMIT側の`LICENSE`・依存通知も、GPL-3.0本文も同梱しなかった。
- 前回追加したCIはRustバイナリをコンパイルするだけで`build-m18.mjs`を実行せず、release auditの対象も2つの`.sdPlugin`に限定していた。

## 3. 根本原因

根本原因は、配布物を「実行に必要なファイルの集合」としてだけ定義し、OSSライセンス通知、プロジェクト識別、各実行経路の依存条件をリリース要件として定義していなかったことにある。

その結果、次の防止線がすべて欠けていた。

- ビルド時に実際のバンドル依存から通知を生成する処理
- 配布物に必須文書があることを落とす監査
- フォーク時にpackage metadataを更新するチェック
- 推奨経路・フルOSS経路を実行環境どおりに検証するCI
- 配布形式ごとに異なる追加ライセンス（M18アダプターのGPL-3.0）を成果物要件へ結び付ける検査

## 4. 影響

- MIT等の通知条件を満たさない配布物を生成できる状態だった。
- 利用者やSBOMツールを上流リポジトリへ誤誘導する可能性があった。
- OSS利用者がVSD Craftのプロプライエタリ依存を方式選択時に判断できなかった。
- Node.js 20/VSD Craft経路とRustアダプターの破損をPR時に検知できなかった。
- フルOSS構成のバイナリ配布でGPL-3.0本文とMIT依存通知が欠落する状態だった。

## 5. プラグインIDの判断

`com.simeo.codex-deck`はmanifest、53アクション、導入先、既存ユーザー設定に使われる永続識別子である。リポジトリ内の情報だけでは`simeo`利用権限を確認できず、機械的な改名は既存シーン・設定を別プラグイン扱いにする移行変更となる。このため今回の修正では推測で改名せず、権利確認と移行方針の決定が必要な残課題として扱う。
