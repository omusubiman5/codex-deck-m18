# VSD Craft / Codex Deck ボタン操作不能の対応報告

## 1. 対応結果

Codex更新へのコマンド実行互換対応と、Microブリッジの自動起動・常駐対応を実装し、VSD Craftへ修正版を配置した。利用者がCodexを特定のショートカットから起動することを前提とせず、VSD Craftプラグイン自身がWindowsブリッジ監視を起動する構成へ変更した。

- 対応日: 2026-08-16（JST）
- 最終配置先: `%APPDATA%\HotSpot\StreamDock\plugins\com.simeo.codex-deck.sdPlugin`
- 最終バックアップ: `%LOCALAPPDATA%\CodexDeck\backups\com.simeo.codex-deck.sdPlugin-20260816-155049`

## 2. コード修正

### 2.1 Codex Tools実行互換

対象: `src/codex-micro-renderer-bridge.ts`

- 従来の直接コマンド呼び出し検出を維持。
- 現行Codexの `permissionWrapper(context, action.command, source)` 形式を検出。
- ラッパー関数の引数・本文から実コマンド実行関数を特定。
- import aliasを逆引きして実行関数をロード。
- 通常のCodex Toolsと環境アクションへ同じ互換処理を適用。
- タスクIDの `local:` 接頭辞を正規化してエージェント切替を判定。

### 2.2 Microブリッジの自動管理

対象:

- `src/windows-bridge-supervisor.ts`
- `src/plugin.ts`
- `scripts/build-vsd-craft.mjs`
- `scripts/validate-vsd-craft.mjs`

対応内容:

1. VSD Craftプラグイン起動時にWindowsブリッジ監視を自動起動する。
2. 監視はプラグインの子プロセスとして保持し、異常終了をプラグインログへ記録する。
3. VSD Craft配布物へ `Start-CodexDeck.ps1`、`Watch-CodexDeck.ps1`、`runtime-override.mjs` を同梱する。
4. ランタイム依存の `launcher/node_modules/ws` も同梱する。
5. VSD Craft検証で上記ファイルと依存の存在を必須チェックする。
6. 監視側のmutexにより重複起動を抑止する。

## 3. 配置・復旧

1. VSD Craftと旧プラグインプロセスを停止。
2. 既存プラグインを時刻付きバックアップへ移動。
3. 修正版VSD Craftパッケージを配置。
4. VSD Craftを再起動。
5. プラグインからブリッジ監視を自動起動。
6. 既存Codexのloopback CDPポート `52157` を再利用し、Microイベントを有効化。

## 5. 再発防止

- VSD Craft成果物の検証にブリッジ監視ファイルと実行依存を追加した。
- プラグイン起動時の監視要求と監視異常終了をログへ残す。
- 現行Codexの権限ラッパー構造と自動監視同梱を回帰テストへ追加した。
- 「Codex Deckショートカットから起動すること」を正常動作の前提から外した。
