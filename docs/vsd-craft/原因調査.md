# VSD Craft / Codex Deck ボタン操作不能の原因調査

## 1. 事象

VSD Craft上のCodex Deck / Codex Toolsボタンが表示される一方、押してもCodex側の操作が実行されない。

- 調査日: 2026-08-16（JST）
- Codex: Windowsデスクトップ版 26.810.7004.0
- VSD Craft: 3.10.188.226
- Codex Deckプラグイン: 0.7.0.2

## 2. 結論

故障はボタン画像や物理デバイスではなく、次の2件が重なったソフトウェア不具合だった。

1. Codex更新後、内部コマンドが直接実行ではなく権限判定ラッパーを経由する形に変わり、Codex Toolsの実行関数を解決できなくなった。
2. Codex Deckが必要とするMicroブリッジの起動・常駐をプラグイン自身が保証せず、外部ランチャーとログイン時ショートカットに依存していた。このためCodexアプリとVSD Craftが起動していても、ブリッジがなければ全ボタンが操作不能になった。

## 3. 証跡

### 3.1 コマンド実行関数の未解決

旧プラグインログでは、Codex Tools操作時に次のエラーが連続していた。

```text
ERROR Keycap DWN failed: Error: Error: Codex command runner is unavailable.
ERROR Keycap DEL failed: Error: Error: Codex command runner is unavailable.
ERROR Keycap DIFF failed: Error: Error: Codex command runner is unavailable.
ERROR Keycap NAV failed: Error: Error: Codex command runner is unavailable.
ERROR Keycap SETUP failed: Error: Error: Codex command runner is unavailable.
ERROR Keycap TERM failed: Error: Error: Codex command runner is unavailable.
```

現行Codexの実装では、コマンド呼び出しが次の形へ変わっていた。

```js
!Zt(context, action.command, `codex_micro_hid`)
function Zt(e,t,n){return ... ? !1 : a(t,n)}
```

従来処理は `runner(action.command, source)` の直接呼び出しだけを検索していたため、ラッパー内部の実行関数 `a` を発見できなかった。

### 3.2 ブリッジのライフサイクル不備

実機調査時にはCodexとVSD Craftの両方が起動中だったが、状態ファイルが古く、プラグインログは次の状態だった。

```text
Codex Micro bridge unavailable: Error: Codex wurde nicht über den Micro-Aktivierungsstarter geöffnet.
Codex host health: local=degraded:local-bridge-unavailable
```

Codex DeckはCodex内部のMicroイベントを使うため、Codex起動時にloopback限定のCDPポートが必要である。ところが従来のVSD Craftプラグインはブリッジ監視を起動せず、別途インストールしたランチャーが動いていることを前提にしていた。アプリの起動有無とブリッジの利用可否が別管理だったことが、利用者から見て「両アプリが起動しているのに押せない」直接原因である。

### 3.3 初回の自動監視同梱修正にあった不足

自動監視をプラグインへ追加した初回修正では、`runtime-override.mjs` が使用する `ws` パッケージを配布物へ含めていなかった。そのため監視は起動したが、ランチャーが次で失敗し再試行した。

```text
Watcher check failed: node:internal/modules/package_json_reader:301
```

これは調査中に検出し、監視を停止したうえで `launcher/node_modules/ws` を配布・検証対象へ追加した。

### 3.4 エージェント切替の独立不具合

Codexは場所によりタスクIDを `local:UUID` または `UUID` で返す。完全一致比較では切替成功後も失敗と誤判定するため、`local:` を除いた正規IDで比較する必要があった。

## 4. 影響範囲

- Codex Toolsのコマンド型ボタン全般
- Codex Microのエージェント・アクションボタン
- エージェント切替の成功判定
- 表示更新は動くが操作だけ失敗する状態を含む

## 5. 根本原因

Codexの非公開内部構造への追従不足に加え、Microブリッジを「プラグインの必須構成要素」としてライフサイクル管理していなかったことが根本原因である。起動手順を利用者へ要求する設計ではなく、VSD Craftプラグインが必要ファイルを同梱し、監視を自動起動する必要があった。
