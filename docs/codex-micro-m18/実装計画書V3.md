# Codex Deck M18 安全反映・実機検証計画書 V3

> **V5訂正**：本書が継承した「危険キー3種」は誤分類であり、V5で撤回した。公式30キーはすべて通常の単押しで使用する。

## 1. 文書情報

- 版：V3
- 作成日：2026-08-20
- 基礎計画：`実装計画書V2.md`
- 対象：V2実装の実機反映、Rust adapterの再現可能ビルド、live Gate
- 原則：稼働中のCodex Desktopおよび他のCodex taskを停止・再起動しない

V2で実装した安全修正を、旧プラグインが稼働している実機へ安全に反映し、静的合格と実機合格を区別して記録する。未実施項目は合格として扱わない。

## 2. 現状と解消対象

1. 実機配置中の`plugin.mjs`、`Watch-CodexDeck.ps1`、`Start-CodexDeck.ps1`が最新buildと不一致である。
2. 稼働中の旧watcherにCodex自動`-ForceRestart`経路が残っている。
3. `cargo`／`rustup`が未導入で、M18直接接続adapterをbuildできない。
4. `m18-events.log`が今回の修正以前の記録である。
5. 5分安定性、最小smoke、危険キー、45操作matrixの実機証跡が揃っていない。

## 3. 安全不変条件

- Codex processへ`Stop-Process`、`taskkill`、終了要求を送らない。
- VSD Craft更新はVSD Craftの通常終了が成立した場合だけ続行し、強制終了しない。
- 配置前にplugin、profile、watcher log、process snapshot、hashを保全する。
- 配置後にCodexの基準processが消失または再生成された場合は即時中止する。
- `APPR`、`DEL`、`PLAY`は隔離した使い捨てtask以外でlive発火させない。
- 多重起動、クラッシュ、強制再起動、二重配送、別scene動作を1件でも検出したら後続Gateへ進まない。

## 4. 実施順序

### Phase A：Rust buildの再現性

1. repository rootへ`rust-toolchain.toml`を追加し、edition 2024対応版を固定する。
2. projectの稼働アプリと分離してRust toolchainを導入する。
3. `cargo build --locked --release --manifest-path m18-adapter/Cargo.toml`を実行する。
4. 生成adapter、`Cargo.lock`、toolchain version、SHA-256を記録する。

### Phase B：配置前Gate

1. `npm run check`、`npm test`、`npm run build:vsd-craft`、profile validation、release auditを実行する。
2. インストール済みpluginとbuild成果物のhash差分を記録する。
3. VSD Craft、plugin、watcher、CodexのPIDと親子関係を記録する。
4. installed plugin、3 profile、watcher logを時刻付きbackupへ複製する。

### Phase C：限定反映

1. 外部observerを先に開始する。
2. watcherを含むVSD Craft runtimeだけを対象にする。
3. VSD Craftへ通常終了を要求し、制限時間内に終了しなければ配置を中止する。
4. build済みpluginをstagingから配置し、hash一致を確認する。
5. VSD Craftだけを1回起動する。Codexは起動、停止、再起動しない。
6. pluginと観測専用watcherが各1個であることを確認する。

### Phase D：live Gate

| Gate | 内容 | 合格条件 |
|---|---|---|
| L0 | 現在のCodexを5分観測 | 基準Codex PID維持、クラッシュ0、意図しない再起動0 |
| L1 | VSD Craft反映後5分観測 | VSD Craft 1、plugin 1、watcher 1、Codex再起動0 |
| L2 | 安全な最小smoke | 下段3面、MIND-、Agent 1が各1回配送 |
| L3 | 非対応command | 理由付き不成立、transport切断0、次操作成功 |
| L4 | 危険キーfixture | 短押し0、1.2秒長押し1、二重発火0 |
| L5 | 45操作matrix | 全45件の配送回数とCodex側結果を記録 |

物理押下が必要なGateは、実押下の証拠が取れない限り未実施とする。自動試験や設定個数で代替しない。

## 5. ロールバック

- 配置に失敗した場合は、VSD Craftを自動再起動せず証跡を保全する。
- backup済みpluginをstaging経由で復元する。
- 旧watcherの自動強制再起動経路はロールバックで再有効化しない。
- Codexはロールバック対象に含めず、終了・再起動しない。

## 6. 完了判定

- Rust adapterが`--locked --release`でbuildできる。
- installed pluginとbuild成果物の対象hashが一致する。
- 観測専用watcherが稼働し、自動`ForceRestart`経路がない。
- Codexを一度も停止・再起動せず限定反映が完了する。
- L0～L5の合否と証跡が実装報告書に記録される。
- 未実施Gateがある場合は「実装完了・実機検証未完了」と明記する。
