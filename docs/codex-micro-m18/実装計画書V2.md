# Codex Deck M18 是正実装計画書 V2

> **V5で撤回**：本書の「危険キー3種」は公式根拠のない誤分類だった。公式30キーはすべて通常の単押しへ戻した。現行仕様は`実装計画書V5.md`を正とする。

## 1. 文書情報

- 版：V2
- 作成日：2026-08-20
- 対象：`インシデントレポートV1.md`で確認したP0／P1指摘
- 前提：V1の必須45操作と3面仕様は維持し、機能削減で解決しない
- リリース状態：本計画の全Gate合格まで停止

本書は、強制再起動、多重起動、画面切替競合、current-view依存commandによる切断、危険キーの誤操作を是正するための実装計画である。広範な機能追加より安全境界の固定を優先する。

## 2. 守るべき不変条件

1. watcher、plugin、startup shortcutは、稼働中Codex Desktopを自動終了しない。
2. Codex再起動は、利用者が影響を確認して明示的に要求した場合だけ許可する。
3. bridge未接続、command非活性、描画失敗をCodex全体の再起動理由にしない。
4. Codex root processとmain windowを同一試験中に増殖させない。
5. 15 LCDキー×3面の45操作、下段3面直接切替、プロジェクト名優先表示を維持する。
6. `APPR`、`DEL`、`PLAY`は危険キーとして通常キーと異なる保護を持つ。
7. 未実施のlive試験を自動テスト合格で代替しない。

## 3. 対象範囲

### 必須

- Windows launcher／watcherの権限分離
- 既存startup shortcutとインストール済みlauncherの安全な移行
- CDP command errorとtransport errorの分離
- シーン切替時の描画世代管理
- 危険キー3種のメタデータ、表示、長押し保護
- テスト計画／結果／READMEの整合
- Windows live安全試験と45操作matrix

### 維持確認

- macOS launcherが明示的な`--restart`なしにCodexを終了しないこと
- Stream Deck、VSD Craft、M18直接接続、relayの既存公開UUID／protocol互換
- Agent 1～6、Usage、Host、Reasoning、公式30キーの機能

### 対象外

- 第4シーンの追加
- 必須45操作の削減
- Codex Desktop本体の改変
- VSD Craft本体の改変または再配布

## 4. Phase 0：変更凍結と証跡保全

### 実装

- 現行のplugin、launcher、watcher、3 profile、関連ログのhashと保存先を記録する。
- `%LOCALAPPDATA%\CodexDeck\watcher.log`と`watcher-recovery.json`を保全する。
- live試験が未完了であることをREADME、実装報告書、テスト結果で統一する。

### 完了条件

- 復元可能なbackupがある。
- 調査証跡を変更後のログで上書きしていない。
- マージ／リリース停止状態が文書化されている。

## 5. Phase 1：自動強制再起動の完全撤去

### 実装

1. startup shortcutから`-RecoverExistingSession`を除去する。
2. watcherから`Invoke-CodexDeckLauncher -ForceRestart`への自動到達経路を削除する。
3. bridgeがない既存Codexを検出した場合は、状態と手動手順を記録して観測を継続する。
4. 通常の`Start-CodexDeck.ps1`実行では、Codex processが存在する場合に`Stop-Process`へ進まない。
5. `Stop-Process`は明示的な`-ForceRestart`指定時だけ許可し、実行前に対象process数と未送信入力への影響を表示する。
6. インストーラー更新時に、旧引数付きstartup shortcutを安全な引数へ置換する。
7. plugin supervisorは観測専用watcherだけを起動し、restart権限を渡さない。

### テスト

- watcherソースに自動`-ForceRestart`呼び出しが存在しない。
- startup shortcut引数に`RecoverExistingSession`が存在しない。
- bridgeなし＋Codex起動中でもprocess終了APIが0回である。
- watcher再起動、bridge degraded、Codex generation交代を繰り返しても終了要求が0回である。
- 明示的な`-ForceRestart`だけが手動再起動経路へ到達する。
- インストール済みファイルとbuild成果物のhashが一致する。

### 完了条件

自動経路と通常起動経路から、稼働中Codexを終了する処理が構造的に到達不能である。回数制限やcooldownだけでは完了としない。

## 6. Phase 2：CDPエラー分類

### 実装

- `codex-micro-renderer-bridge.ts`へ判別可能なエラー分類を導入する。
- current-viewでcommandが非活性、未対応keycap、前提不足をcommand rejectionとして返す。
- WebSocket切断、timeout、protocol破損、renderer消失だけをtransport errorとして扱う。
- command rejectionでは接続を維持し、対象キーだけに理由付きalertを返す。
- transport error時だけ接続を破棄し、次回pollで再接続する。

### テスト

- PRなどを非対応viewで実行しても`disconnect()`が呼ばれない。
- 直後の有効なキーが再接続待ちなしで動作する。
- timeoutとsocket closeでは接続が破棄される。
- 同一入力が再接続後に二重配送されない。

### 完了条件

操作上の不成立がCDP churn、次キーの無反応、Codex再起動へ波及しない。

## 7. Phase 3：シーン描画の世代管理

### 実装

- 各物理action IDにregistration generationまたはtokenを付与する。
- register時に新tokenを発行し、unregister時に失効させる。
- 非同期画像取得後、`setImage`直前に現在の登録tokenと一致することを確認する。
- 旧sceneの遅延描画結果は破棄し、新sceneの画像を変更しない。
- scene切替中のkey-down ownershipは既存どおり保持し、key-upを元bindingへ配送する。

### テスト

- 旧scene画像Promiseを意図的に遅延させ、新scene描画後に解決しても上書きしない。
- 1→2→3→1の高速切替で最終sceneだけが表示される。
- 押下中にsceneを切り替えてもreleaseが元操作へ1回だけ届く。
- Usage、Host、Agent、keycapの全rendererで同じ世代規則を適用する。

### 完了条件

切替順序や画像取得時間に依存せず、表示面と操作bindingが常に一致する。

## 8. Phase 4：危険キー3種の保護

### 実装

- 公式keycap定義へ`dangerous`メタデータを追加し、対象を`APPR`、`DEL`、`PLAY`の3件に固定する。
- 3キーは警告色、危険表示、hold進捗を持ち、通常キーと視覚的に区別する。
- 短押しでは実行せず、1.2秒以上の長押し完了時に1回だけ配送する。
- 長押し途中のscene切替、接続断、key-up欠落では実行しない。
- VSD Craft、Stream Deck、M18直接接続で同じ危険キー規則を共有する。
- `GIT`、`MRG`、`PR`は現行どおり画面／フローを開く操作とし、押下だけでcommit、merge、PR公開を確定しないことを回帰確認する。

### テスト

- 1.2秒未満で配送0回。
- 1.2秒以上で配送1回。
- key repeat、二重key-up、scene切替を含めても最大1回。
- 危険キーが正確に3件で、READMEの記載と一致する。
- VSD Craft profileと実機表示で通常キーとの差を確認する。

### 完了条件

危険キー3種が文書だけでなく、表示と入力処理の両方で保護される。

## 9. Phase 5：テストの実効性改善

### 自動試験

- ソース文字列の存在確認だけのテストを、呼び出し回数と状態遷移を検証するbehavior testへ置き換える。
- 45 catalogとVSD Craft profile生成定義を単一ソース化し、手書き二重定義をなくす。
- 全45操作について、物理入力からcontroller／bridgeまでの配送先と回数を表形式fixtureで検証する。
- `git diff --check`をCIへ追加し、末尾空白を失敗にする。
- `npm run check`、`npm test`、`npm run build`、`npm run validate:vsd-craft`、`npm run build:m18`、`npm run audit:release`を必須化する。

### live Gate

live試験は対象Codex task自身から起動・停止せず、別terminalまたは外部観測者が実施する。

| Gate | 試験 | 合格条件 |
|---|---|---|
| L0 | Codex単純起動5分 | root 1、main window 1、クラッシュ0、意図しない再起動0 |
| L1 | VSD Craftを1回追加起動して5分 | Codex 1、VSD Craft 1、watcher 1、強制再起動0、クラッシュ0 |
| L2 | 最小smoke | 下段3面、MIND-、割当済みAgent 1が各1回配送される |
| L3 | 非対応command | 理由付きalert、CDP切断0、次の有効操作成功 |
| L4 | 危険キー | 影響を隔離したfixture／taskで短押し0、長押し1 |
| L5 | 45操作matrix | 45件すべてで配送回数とCodex側効果または理由付き不成立を記録 |

停止条件は、多重起動、クラッシュ、強制再起動、二重配送、別scene動作、意図しない危険操作のいずれかを1回検出した場合とする。

## 11. 実装順序

1. Phase 0で証跡を保全する。
2. Phase 1の自動強制再起動撤去だけを先に実装・レビューする。
3. Phase 1のオフライン試験合格後、Phase 2とPhase 3を個別commitで実装する。
4. Phase 4の危険キー保護を共通部品として実装する。
5. Phase 5の自動試験を全件通す。
6. 外部観測下でlive Gate L0から順番に実施する。
7. L0またはL1が失敗した場合、M18キー試験へ進まない。
8. 全Gate合格後に文書と配布物を同期し、改めて鬼レビューを実施する。

## 12. リファクタリング境界

安全修正と同時に、次の責務だけを分離する。

- launcher：通常起動、観測、明示的手動再起動
- bridge：command rejection、transport failure、protocol failure
- rendering：registration lifecycle、generation、image cache
- key input：通常キー、press/releaseキー、長押し危険キー
- layout：45操作catalog、3 scene、VSD Craft profile

`DeckController`全体の大規模分割や新機能追加はlive安全性を回復した後に行う。1 commitで複数の安全境界を同時変更しない。

## 13. ロールバック

- launcher／watcher更新前にインストール済みファイルとstartup shortcutをbackupする。
- profile更新前に3 profileを別ディレクトリへ退避する。
- plugin更新前に現行pluginをversion付きで保存する。
- live Gateで停止条件に該当した場合はアプリを自動再起動せず、読み取り専用ログを採取して前版へ戻す。
- ロールバック後も自動強制再起動を再有効化しない。

## 14. 最終完了条件

次をすべて満たした場合だけ是正完了とする。

- 自動または通常起動経路からCodex process終了へ到達できない。
- 明示的手動再起動以外の`Stop-Process`実行が0回である。
- current-view依存commandの不成立でCDP接続を維持する。
- scene高速切替後に旧描画が残らない。
- 危険キー3種は短押しで実行されず、長押し時だけ1回実行される。
- 45操作と下段3面切替が実機で確認される。
- L0～L5の証跡が揃い、未実施項目がない。
- Windows／macOSの維持対象経路が回帰していない。
- README、テスト結果、実装報告書、配布物が一致する。
- 最終鬼レビューでP0／P1指摘がない。
