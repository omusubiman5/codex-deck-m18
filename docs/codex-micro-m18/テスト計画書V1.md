# Codex Deck M18 テスト計画書 V1

## 1. 目的と最優先事項

最優先は機能数ではなく、Codex DesktopとVSD Craftが単一起動のまま安定することとする。単純起動、安全性、監視回路の順に合格するまで、M18の機能試験へ進まない。

以前の計画は45操作の配送確認を先行し、クラッシュ、Codex多重起動、VSD Craft多重起動、自動回復ループを停止条件として定義していなかったため無効とする。

## 2. 絶対停止条件

次のいずれかを1回でも検出した時点でlive試験を中止する。

- Codex Desktopのroot processまたはmain windowが2個以上になる。
- VSD Craftの親processが2個以上になる。
- CodexまたはVSD Craftがクラッシュする。
- 監視処理が同じsessionで2回目の強制再起動を要求する。
- bridge degraded状態を理由に稼働中のCodexを繰り返し再起動する。
- 試験担当自身が動作しているCodex task内から、対象Codexの停止・再起動を行う必要が生じる。

停止後は機能試験の結果を合格として記録しない。process、window、watcher logを読み取り専用で採取し、オフライン修正へ戻る。

## 3. 試験段階

### Gate 0: オフライン安全試験

| ID | 内容 | 合格条件 |
|---|---|---|
| SAFE-01 | plugin supervisorの引数検査 | `RecoverExistingSession`を渡さない |
| SAFE-02 | watcher単一起動 | named mutexが存在する |
| SAFE-03 | 主process数ガード | main processが1個以外なら自動回復しない |
| SAFE-04 | lifecycle予算 | watcher生存中の自動回復は最大1回 |
| SAFE-05 | 永続回路遮断 | 回復試行後30分は別watcherでも自動回復しない |
| SAFE-06 | 先行記録 | 強制再起動の前に回復試行を保存する |
| SAFE-07 | 型・回帰 | `npm run check`と`npm test`が合格する |

### Gate 1: Codex単純起動

この試験は、試験対象ではない別terminalまたは手動観測から行う。Codex内の実行中taskからCodex自身を再起動しない。

1. 自動起動対象を増やさないclean sessionを用意する。
2. Codex Desktopを1回だけ起動する。
3. 5分間、root process数、main window数、クラッシュ有無を観測する。
4. root process 1、main window 1、クラッシュ0、意図しない再起動0なら合格とする。

### Gate 2: VSD Craft追加起動

Gate 1合格状態を維持したままVSD Craftを1回だけ起動する。

1. 5分間、CodexとVSD Craftのroot process／main window数を観測する。
2. plugin supervisorが観測専用で起動し、Codexを強制再起動しないことを確認する。
3. Codex 1、VSD Craft 1、クラッシュ0、意図しない再起動0なら合格とする。

### Gate 3: 最小smoke

Gate 2まで合格後、破壊性のない操作だけを次の順で1回ずつ試す。

1. 下段3ボタンでProjects／Keys 1／Keys 2を各1回選択する。
2. Projects面でMIND-を1回試す。
3. Agent 1を、割当が確認できる場合だけ1回試す。
4. 操作ごとに配送1回、handler 1回、状態変化または理由付きalert 1回以下を確認する。

クラッシュ、多重起動、二重配送があれば即時停止する。

### Gate 4: 45操作matrix

Gate 3合格後に限り、3面×15操作を個別に確認する。Reset、archive、PR作成、remote host切替など状態変更を伴う操作は、事前条件と影響を明示して別枠で実施する。

## 4. 45操作の対象

| 画面 | 操作 | 件数 |
|---|---|---:|
| Codex Projects | Agent 1～6、上下左右、MIND-、Host、Usage Limit、Usage Overview、Reset | 15 |
| Codex Keys 1 | FAST、APPR、REJ、SPLIT、MIC、CODEX、BUG、OAI、TERM、DWN、DEL、NEW、NAV、MAGIC、DIFF | 15 |
| Codex Keys 2 | PLAY、GIT、BRCH、MRG、PR、PAINT、LAB、PARTY、TIME、MIND+、MIND-、SETUP、FOLD、UPL、APPS | 15 |

下段3物理ボタンは全画面でProjects／Keys 1／Keys 2への直接切替とする。

## 5. 証跡と判定規則

- オフライン試験：command、exit code、test件数、失敗件数を記録する。
- live試験：開始前後のroot process数とmain window数、経過時間、クラッシュ回数を必須証跡とする。
- UI表示だけでは起動安定性の合格としない。
- profile配置だけでは操作機能の合格としない。
- handler到達だけではCodex側機能の合格としない。
- 未実施、未観測、観測不能は合格にしない。

## 6. 実行責任の境界

このCodex task内で安全に完結できるのはGate 0までである。Gate 1以降は、対象Codex自身を試験主体にするとクラッシュ時に証跡と制御を同時に失うため、別terminalまたは利用者の手動観測で行う。Gate 1とGate 2が合格するまで実機への再配布や全キー試験は行わない。
