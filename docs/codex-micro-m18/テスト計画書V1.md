# Codex Deck M18 テスト計画書 V1

## 1. 目的

VSD Craft経由のM18で「1画面目はMIND-以外が無反応、2画面目も不安定」という症状を再現・分解し、45操作について次の各層を独立に判定する。

1. profile配置が正しい。
2. M18押下がVSD Craftへ届く。
3. VSD CraftがCodex DeckプラグインへkeyDown／keyUpを配送する。
4. プラグインが正しいhandlerを呼ぶ。
5. Codex Desktopの現在状態でcommandが成立する。
6. 失敗時にalertまたは診断ログが残り、「無反応」に見えない。

## 2. 対象環境

- Windows 11
- VSD Craft 3.10.202.0702
- VSD Inside M18 / VSDM18
- Codex Desktop
- Codex Deck VSD Craft package
- branch: `codex/feature/m18-v1`

## 3. 対象盤面

| 画面 | 操作 | 件数 |
|---|---|---:|
| Codex Projects | Agent 1～6、上下左右、MIND-、Host、Usage Limit、Usage Overview、Reset | 15 |
| Codex Keys 1 | FAST、APPR、REJ、SPLIT、MIC、CODEX、BUG、OAI、TERM、DWN、DEL、NEW、NAV、MAGIC、DIFF | 15 |
| Codex Keys 2 | PLAY、GIT、BRCH、MRG、PR、PAINT、LAB、PARTY、TIME、MIND+、MIND-、SETUP、FOLD、UPL、APPS | 15 |

下段3物理ボタンは、全画面でProjects／Keys 1／Keys 2への直接Scene Shiftとする。

## 4. 合否基準

### 4.1 profile

- 各画面にLCD操作が15件ある。
- 45件が期待順で、重複・欠落・未登録UUIDがない。
- 各画面にScene Shiftが3件あり、同一の3 profileを左・中央・右の順で指す。

### 4.2 plugin

- manifestの全UUIDに実装handlerがある。
- keyDown／keyUpが必要なAgent、Joystick、MIC、Encoderで両イベントを扱う。
- command失敗時にerror logとshowAlertを出す。
- current view依存、remote未接続、bridge未準備を異なるエラーとして識別できる。

### 4.3 実機

- VSD CraftがM18をUSB openする。
- active画面の15件にwillAppearが発生する。
- 物理押下後、対応する成功または明示的な失敗ログが1件だけ記録される。
- 画面切替後も別画面のhandlerへ誤配送されない。
- 操作成功を、対象画面・状態・表示変化のいずれかで確認できる。

## 6. 実行順序

1. 現在のprofile、plugin、ログを読み取り専用で採取する。
2. CFG／REGテストを実行し、配置・登録ミスを先に除外する。
3. 自動テストとpackage検証を実行する。
4. VSD Craft UIで3面と現在選択面を確認する。
5. 既に記録された実押下ログを操作別に集計する。
6. 安全な操作を再試験し、成功・明示的失敗・未試験へ分類する。
7. archive、reset credit消費、PR作成など状態変更が大きい操作はmockで配送経路を検査し、liveでは実行直前までに限定する。
8. 原因、修正要否、再試験結果を`テスト結果V1.md`へ記録する。

## 7. 証跡

- VSD Craft logのplugin connected、USB open、willAppear
- Codex Deck plugin logのaction success／failure
- profile／manifest／handler照合結果
- npm check／test／build／validate結果
- VSD Craft画面の目視確認

ログにはtask IDや端末serialを転記せず、結果文書では必要な判定だけを記録する。
