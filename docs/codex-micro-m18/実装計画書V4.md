# Codex Deck M18 L2～L5検証基盤 実装計画書 V4

> **V5で撤回**：本書の危険キーclock注入と長押し試験は誤分類に基づく。V5で実装・試験とも撤去し、公式30キー全件を通常の単押しへ戻した。

## 1. 文書情報

- 版：V4
- 作成日：2026-08-20
- 前提：V3で最新plugin再読込と再読込後L1まで合格済み
- 対象：残るL2～L5の安全な実施基盤と証跡

## 2. 目的

45操作の定義個数だけでなく、各操作がcontrollerの正しい配送先へ正しい回数で到達することを自動検証する。また、稼働中のVSD Craft、plugin、watcher、Codex、配置hash、VSD接続ログを読み取り専用で検査する。

自動検証は物理押下の代替とはしない。物理M18からの入力とCodex側効果が必要な項目は、実押下証跡が得られるまで未実施と記録する。

## 3. 安全境界

1. CodexおよびVSD Craftを本計画の検査で停止・再起動しない。
2. live readinessは読み取り専用とし、PID、hash、logだけを取得する。
3. `APPR`、`DEL`、`PLAY`を稼働中Codexへ自動発火しない。
4. 45操作matrixはrecording controllerへ配送し、実Codex bridgeへ接続しない。
5. 危険キーは注入clockで短押し、長押し、cancel、二重発火を決定論的に検証する。
6. 物理実押下を自動試験合格で代替しない。

## 4. 実装

### Phase 1：危険キーclock注入

- `createM18Binding`へ任意の`dangerousHoldFactory`を追加する。
- production既定値は従来どおり1.2秒の`HoldToConfirm`とする。
- testだけが注入clockを使い、production挙動を変更しない。

### Phase 2：45操作dispatch matrix

- 45件すべてを`createM18Binding`で生成する。
- recording controllerへdown／upを配送する。
- Agent、joystick、encoder、host、Usage、reset、MIC、通常keycap、危険keycapごとに呼出先・引数・回数を照合する。
- 危険キー3件は短押し0回、1.2秒長押し1回を個別確認する。

### Phase 3：live readiness

- installed pluginとbuild成果物の主要4 hashを比較する。
- Codex root/main、VSD Craft、plugin、watcherが各1 processであることを確認する。
- installed watcherが観測専用で`ForceRestart`を持たないことを確認する。
- 最新VSD Craft logでCodex Deck plugin接続とM18 `willAppear` 15件以上を確認する。
- JSON証跡を`%LOCALAPPDATA%\CodexDeck\live-runs`へ保存する。
