# Codex Deck M18 安定化実装報告書 V6

## 1. 結果

2026-08-29時点の実ログ、ソース、既存テスト、Codex Desktop 26.820.10647.0の読み取り専用確認を基に、VOICE TALKと同一障害系列にあるCDP競合、M18 adapter切断、ack無応答、ログ肥大、watcher再試行を修正した。

実通話の開始・終了、実機USB抜差し、VSD Craftとの排他切替は行っていない。コミット、push、設定変更、依存version更新も行っていない。

## 2. 診断の分類

### 実害が確認済み

| 重要度 | 発見 | 根拠 | 対応 |
|---|---|---|---|
| Critical | snapshotと入力commandのCDP評価が競合し、timeout時に全pendingが失敗 | `m18.log`にRuntime.evaluate 5秒timeout 475件、bridge unavailable 569件 | 優先度付き直列queue、送信前限定再接続、snapshot cache |
| High | USB/HID切断後に描画Promiseがrejectしruntimeがexit code 1で終了 | `HidError(Disconnected)`後のstack traceを4系列確認 | adapter ready後exit/error通知、controller停止、watcher再起動への明示移行 |
| High | adapter起動失敗が5秒固定で反復 | `spawn UNKNOWN` 1,231件、runtime exit 1,242件 | watcherを5→10→20→40→60秒backoff、安定後5秒へ復帰 |
| Medium | frameログが無制限増加 | 6日で334,935行、56,692,062 bytes | event 2MiB、frame/watcher 8MiB、`.previous` 1世代rotation |
| Medium | watcher native redirectのencoding混在 | NULと文字化けを実ログで確認 | PowerShell `Add-Content -Encoding UTF8`へ統一 |

VOICE物理入力自体は70 down／70 upで欠落がなかった。一方、短時間の再押下があり、現行`composer.startVoiceMode`がactive時には終了側へtoggleすること、single-flightがないこと、結果前に成功pulseを出すことが不安定性の主要因だった。

### 再現可能な不具合

- adapterがackを返さない場合、従来のcommand Promiseは永久にpendingとなった。偽adapterで再現し、有限timeoutを追加した。
- 複数CDP評価を並行送信できた。queue単体テストで最大同時実行数1、待機commandのsnapshot追越しを確認した。
- Voiceの同時開始と成功直後の再開始を許していた。single-flightと5秒settling windowのテストを追加した。
- Voice失敗時も先にpulseしていた。成功時だけpulseし、失敗時は赤いRETRY表示後に静止表示へ戻すよう変更した。

### 高リスクな潜在不具合（今回非対象）

- `control-target.json`がatomic writeではない。
- session ownershipが定期的にsession treeを走査するため、大規模環境ではI/O負荷が増える可能性がある。
- Codexのprivate module、command registry、React fiber、Voice surface URLは将来変更され得る。
- USB切断がkey-downとkey-upの間に起きる場合のpress ownershipは実機未検証。
- `npm audit`は開発依存の推移依存`brace-expansion`、`fast-uri`、`tar`をHigh 3件と報告した。`npm audit --omit=dev`は0件で、配布runtime依存への該当は確認されなかった。依存更新は今回の権限外かつ変更範囲外のため未実施。

### ログ上のノイズ／想定内

- relay未設定時の`remote=offline:relay-disconnected`。
- sidebarにないtaskの直接選択拒否。
- VSD Craft installerがdirect startupを`disabled-startup`へ移すこと。
- observation-only watcherが通常起動Codexを再起動せずbridgeなしと記録すること。

## 3. 変更内容と原因への対応

### CDPとsnapshot

- `PrioritySerialQueue`を追加し、`Runtime.evaluate`を直列化した。
- 待機中は`command`を`snapshot`より優先した。実行中snapshotのpreemptionはせず、破壊的な途中切断を避ける。
- 接続に失敗した場合だけ送信前に1回再接続する。実行済みか不明なtimeout後のVoice commandは再送しない。
- renderer lifetime内でasset modules、settings definitions、event bus、slot resolverを`Symbol.for(...)` cacheへ保存し、各pollの全module探索を除去した。

### VOICE TALK

- `VoiceStartGate`で同時処理を1件に制限し、成功後5秒は後続tapを抑止した。
- 現行CodexのVoice composition surfaceを検出した場合は`already-active`としてcommandを送らず、start-only相当とした。
- 成功後だけ紫pulseを出し、`already-active`／`suppressed`では表示を変えない。
- 失敗時は赤いVOICE TALK／RETRYを900ms表示し、その後静止表示へ復帰する。
- transport接続前の限定retryだけを許し、toggle相殺につながるcommand再送はしない。

### M18 adapterとwatcher

- JSON Lines commandへ既定5秒のack timeoutを追加し、timerをack、error、exit時に必ず解放する。
- ready後のchild exit/errorを一度だけruntimeへ通知する。
- runtimeはsceneとcontrollerを停止し、非zero終了としてwatcherの再接続経路へ戻す。
- watcher出力をUTF-8へ統一し、ログrotationと最大60秒の段階的backoffを追加した。
- wire format、scene配置、物理キー割当、設定schemaは変更していない。

## 7. 残存リスク

- 実行中snapshotがtimeoutする場合、直列queueのcommandは最大5秒待つ。次のjobではcommandが優先される。
- CodexがVoice surface URLを変更するとactive guardが効かない。その場合もsingle-flightとsettling guardは残る。
- private runtime objectがrenderer reloadなしでhot-swapされる場合、snapshot cacheが古くなる可能性がある。
- watcherが長期連続失敗した後の復旧検出は最大60秒遅れる。
- 開発依存High 3件は別変更として評価・更新が必要である。

## 8. 推奨修正順

今回のP0/P1系列（CDP直列化、Voice guard、adapter lifecycle、ack timeout）は実装済み。次は、実機でのUSB再接続とVoice phase試験を優先し、その後に`control-target.json` atomic write、session scan負荷計測、開発依存脆弱性更新をそれぞれ独立変更として扱う。

## 9. ロールバック

設定schema、永続化形式、wire formatを変更していないためmigrationは不要である。上記実装ファイルと追加テスト・文書の差分を個別に戻せる。配布後は直前releaseの`dist/m18`と`Watch-CodexDeck-M18.ps1`へ戻す。ログの`.previous`は診断用であり、rollback時に削除する必要はない。
