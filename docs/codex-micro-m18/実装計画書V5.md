# Codex Deck M18 公式30キー通常操作復元 実装計画書 V5

## 1. 文書情報

- 版：V5
- 作成日：2026-08-20
- 対象：Codex Desktopから取得する公式30キー
- 目的：根拠なく追加された「危険キー3種」と長押し保護を撤去し、公式30キーすべてを通常の単押しで使用可能にする

## 2. 正しい仕様

公式30キーは次の30種類であり、すべて同じ通常キー入力規則を使用する。

`FAST`、`APPR`、`REJ`、`SPLIT`、`MIC`、`CODEX`、`BUG`、`OAI`、`TERM`、`DWN`、`DEL`、`NEW`、`NAV`、`MAGIC`、`DIFF`、`PLAY`、`GIT`、`BRCH`、`MRG`、`PR`、`PAINT`、`LAB`、`PARTY`、`TIME`、`MIND+`、`MIND-`、`SETUP`、`FOLD`、`UPL`、`APPS`

- `APPR`は承認操作であり、独自の危険キーではない。
- `REJ`は拒否操作であり、独自の危険キーではない。
- `DEL`は現行実装ではチャットのアーカイブであり、Taskの不可逆削除ではない。
- `PLAY`は設定済み環境アクションを呼び出す通常の公式キーである。
- 公式仕様に「危険キー3種」という分類はない。
- `Rate-limit Reset`は公式30キーとは別の専用機能であり、credit消費を伴うため既存の長押し確認を維持する。

## 3. 撤去対象

1. `DANGEROUS_KEYCAP_IDS`と`isDangerousKeycap`。
2. 公式キー用`HoldToConfirm`。
3. Stream Deck／VSD Craft actionの長押し分岐。
4. M18直接接続bindingの長押し分岐と試験clock注入。
5. 赤枠、保持進捗、危険キー用controller state。
6. READMEおよび現行テスト文書の「公式30キー中3種が危険」という記載。
7. 危険キー専用テスト。

過去のV2～V4計画書・報告書とインシデントレポートは当時の誤った判断の履歴として保持し、V5で撤回されたことを明記する。

## 4. 実装

### Phase 1：入力処理

- `DirectKeycapAction.onKeyDown`から30キーすべてを即時に`runKeycap`へ配送する。
- `onKeyUp`は公式キー実行に使用しない。
- `createM18Binding`の全keycapを単押し時に1回だけ`runKeycap`へ配送する。
- `MIC`だけはCodex Microのpress／release仕様を維持する。

### Phase 2：表示

- 公式キーの赤枠と長押し進捗表示を撤去する。
- 全30キーを通常の公式keycap描画に統一する。
- Rate-limit Resetの保持進捗表示は維持する。

### Phase 3：試験

- 公式30キーが正確に30件であることを検証する。
- `APPR`、`DEL`、`PLAY`を含む通常keycapが1回のdownで1回配送され、upでは追加配送されないことを検証する。
- 45操作dispatch matrixを更新する。
- Resetの短押し防止と長押し実行が維持されることを検証する。

### Phase 4：文書・実機

- READMEを公式30キー通常操作へ修正する。
- 実機テスト実行票から危険キーGateを撤去する。
- build、profile、release audit後に実機pluginへ配置する。
- Codexを停止・再起動せず、VSD Craftだけを限定再読込する。
- readinessと単一起動観測を実施する。

## 5. Gate

| Gate | 合格条件 |
|---|---|
| G1 | TypeScript check error 0 |
| G2 | 全自動試験 fail 0 |
| G3 | 公式30キーが30件、全件manifest actionあり |
| G4 | APPR／DEL／PLAYを含む通常keycapが単押し1回で配送1回 |
| G5 | Rate-limit Resetの長押し保護が維持される |
| G6 | 3面、45操作、9直接切替のprofile validation合格 |
| G7 | release audit合格 |
| G8 | installed pluginとbuild hash一致、各process 1、plugin接続済み |

## 6. 完了条件

- 公式30キーの独自危険分類がコード、表示、README、現行試験から消えている。
- 30キーすべてが通常の単押し操作として実装されている。
- Rate-limit Resetだけは別機能として長押し確認を維持している。
- 実機pluginへ反映され、Codexを再起動せずreadinessに合格している。
- V5実装報告書へ変更、試験、配置、残る物理実押下を記録する。
