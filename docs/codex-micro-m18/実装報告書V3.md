## 3. 作成・変更した実装

### 3.1 再現可能なRust build

- repository rootへ`rust-toolchain.toml`を追加した。
- `image 0.25.10`のMSRVに合わせ、Rustを`1.88.0`へ固定した。
- `rustup 1.29.0`を導入した。
- 管理者権限不要のWinLibs UCRTと`1.88.0-x86_64-pc-windows-gnu`を導入した。
- M18 adapterを`--locked --release`でbuildした。

生成物：

- `m18-adapter/target/release/codex-deck-m18-adapter.exe`
- SHA-256：`6DDFC1C9CD4B9A900106D52288B0B298164168339DB2836FA272B7BFF8708217`
- `dist/m18`へのpackage生成：成功

途中で確認した課題：

1. Rust 1.85.1では`image 0.25.10`が要求するRust 1.88を満たさなかった。
2. MSVC hostでは`link.exe`がなく、Visual C++ Build Tools導入はUAC未承認で終了コード1602になった。
3. GNU targetだけの指定ではbuild scriptがMSVC hostでリンクされるため、host toolchain自体をGNUへ変更して解決した。

### 3.2 live observer

`scripts/Observe-CodexDeck-Live.ps1`を追加した。

- Codex UI最上位processを、親が別のCodex UI processではないPIDとして識別する。
- 主要app-serverを`features.code_mode_host=true`で識別する。
- VSD Craft、plugin、watcherを5秒間隔でJSON Linesへ記録する。
- PID署名の変化と最終process数をsummary JSONへ出力する。

初回実装ではElectron childをすべてrootとして数えたため判定器を修正し、正しい条件でL0を再実行した。初回結果を合格証拠には使用していない。

### 3.3 安全配置script

`scripts/Deploy-VSDCraft-CodexDeck-Safely.ps1`を追加した。

- Codex UI rootと主要app-serverの基準PIDを保護する。
- installed plugin、対象3 profile、watcher log、M18 event logをbackupする。
- profile backupは全profileの再帰copyを避け、Codex M18の3 profileだけを`robocopy`で保全する。
- 通常配置ではVSD Craftの正規終了が成立しない限り続行しない。
- `-HotPatchRunning`ではVSD CraftとCodexを継続稼働させたまま配布ファイルを更新する。
- hot patch後はwatcherだけを終了し、観測専用版を1個だけ再起動する。
- 配置後に主要4ファイルのSHA-256一致とCodex基準PID維持を確認する。
