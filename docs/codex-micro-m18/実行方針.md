# 実行方針: Codex Micro互換版の導入

具体的な段階実装、リファクタリング境界、テスト、移行方法は[実装計画書V1](実装計画書V1.md)を正とする。

## 手順

1. ニーズと修正境界を文書で固定する。
2. 6 Agent、Joystick 4方向、Reasoningエンコーダ押下／増減を実装・確認する。
3. 公式30キーをmanifestと実装へ全件登録し、リストとの完全一致を機械検査する。
4. New Task、ホスト切替＋health、Usage Limit、Usage Overview、Rate Limit Resetを実装・確認する。
5. 45操作を15件ずつ3シーンへ配置し、下段3ボタンから各面へ直接切り替えられるようにする。
6. TypeScript型検査、既存全テスト、ジェスチャ、30キー完全性、Usage／Reset、ホスト切替のテストを実行する。
7. M18配布物とVSD Craft向け配布物を再ビルドする。
8. `%LOCALAPPDATA%\CodexDeck\M18`へ直接HID構成の更新物を配備し、VSD Craft構成では標準プラグイン配置を検証する。
9. Codex Desktopを停止せず、常駐watcherだけを観測専用の更新版へ切り替える。
10. CDP接続、USB接続、タスク同期、実機キーイベントをログで確認する。

## 完了条件

- Agent 1～6、Joystick上・下・左・右、Reasoningエンコーダ押下、Reasoning effort増減が実機または同等の統合検証で動作する。
- `OFFICIAL_KEYCAP_IDS`が30件で重複なく、30件すべてにmanifest登録、実行経路、テストがある。
- New Taskがローカルの新規タスク作成を開く。
- Windows／Macホスト切替が対象ホストとhealth表示を更新し、その後の対象依存コマンドを選択先へ配送する。
- Usage LimitとUsage Overviewが5時間／週次の値を表示し、Rate Limit Resetが長押し確認なしには発火しない。
- 45個の必須操作が重複なく15件×3シーンへ収まり、欠落も余剰もない。
- 下段左・中央・右がシーン1・2・3へ直接切り替わり、45操作の数には含まれない。
- 既存テストを壊さず、新規テストも合格する。
- インストール先のNodeランタイムとHIDアダプターが起動し、Codex DesktopとM18の両方へ接続する。
- 実機ボタン入力が`m18-events.log`に記録される。

上記のいずれかを未検証・未実装のまま残す場合は未完了とし、将来対応として完了判定から外さない。
