# Codex Deck M18 テスト結果 V1

## 1. 判定

**総合判定：不合格（配置不良は修正済み、Codex bridge互換性は未解消）**

3面45操作のprofile配置、manifest、handler登録、TypeScript、自動テスト、VSD Craft packageは合格した。実機調査では第3面のactive page設定不良とCodex Deck pluginの二重起動を検出し、修正後の再試験に合格した。

ただし、Codex Desktopの現在ランタイムでMicro slot signalsを取得できず、Projects面が`Signals uncertain`、Hostが`RECONNECT`となった。35秒の監視でもlocal healthはreadyへ復帰しなかった。この状態ではAgentや一部のMicro操作を機能合格にできない。

## 3. 検出した問題

### 3.1 第3面のactive page設定不良

初回配置では`Codex Keys 2`のroot `Actions`だけを書き換え、`Pages.Current`がメーカー既定の子profileを指したままだった。そのため、VSD Craftのprofile名は`Codex Keys 2`でも実画面はメーカー既定操作だった。

再現validator：

```text
Codex Keys 2: active VSD Craft page is not the rewritten root profile.
```

設定生成器を修正し、3面すべてで`Pages.Current`と`Pages.Pages`を各root profile自身へ固定した。修正後はVSD Craft UIで`PLAY`～`APPS`の15件を目視確認した。

### 3.2 Codex Deck pluginの二重起動

旧VSD Craftプロセスの子だったCodex Deck pluginが孤児化し、新VSD Craft配下のpluginと同時に動いていた。これにより同一bridgeへのpoll、接続ログ、状態更新が重複していた。

旧・新のpluginプロセスを停止してVSD Craftを再起動し、再試験時はCodex Deck pluginが1プロセスだけであることを確認した。

### 3.3 Codex Micro slot signals取得不能

二重起動解消後もlive bridgeは次のエラーとなった。

```text
Codex Micro slot store was not found.
```

VSD Craft UIでもAgent 6件は`Signals uncertain`、Hostは`RECONNECT`を表示した。CDP WebSocket自体への接続はできているが、現在のCodex Desktop rendererからMicro slot store／signalsを発見できていない。これはUSB、VSD profile、action UUIDではなく、Codex内部ランタイム検出層の不合格である。

### 3.4 「押しても動かない」操作の仕様差

Projects面の下段は同じ種類の操作ではない。

- `MIND-`：押下操作。利用者確認では動作。
- Host：remote hostが未接続なら切替失敗となりalertを出す。
- Usage Limit：表示専用。現在の実装にはkeyDown handlerがない。
- Usage Overview：表示専用。現在の実装にはkeyDown handlerがない。
- Reset：1.2秒長押し。短押しでは発火しない。

したがって、MIND-以外が短押しで反応しない現象には、bridge障害に加えて表示専用／長押し／remote必須という操作契約も含まれる。ボタンとして短押し反応を期待するなら仕様変更が必要である。

### 3.5 Keys 1のcurrent view依存

実押下ログから、VSD Craftからpluginへの配送自体は確認できた。一方、Codex側で次のエラーとなった。

| 操作 | 結果 | 分類 |
|---|---|---|
| APPR | `This Codex command is not active in the current view` | current view依存 |
| REJ | 同上 | current view依存 |
| SPLIT | 同上 | current view依存 |
| DWN | 同上 | current view依存 |
| OAI | `Codex VS Code event module is unavailable` | runtime module欠落 |

これは物理キーの無配送ではなく、plugin handler実行後にCodex commandが拒否した証拠である。ただし利用者からはalert以外の結果がなく、「無反応」に見える。

## 7. 残課題

優先度順に次が必要である。

1. 現行Codex Desktopに合わせてMicro slot store／signals探索を修正する。
2. bridgeがdegradedの間、利用者に操作不能理由を各キーまたは共通healthで明示する。
3. Usage Limit／Overviewを表示専用とするか、短押し操作を追加するかを正本仕様で確定する。
4. current view依存キーは、使用可能条件を表示するか、安全なfallbackを定義する。
5. OAIのVS Code event module依存を現行Codexで再調査する。
6. bridge ready後に全45操作を実押下し、成功／alert／状態変化を1件ずつ記録する。

現時点では、M18 profile配置は合格だがCodex操作面はリリース合格ではない。
