## 3. P0：自動強制再起動の撤去

### 3.1 変更内容

- Windows startup shortcutから`-RecoverExistingSession`を除去した。
- watcherから回復判定、回復回数、cooldown、`Invoke-CodexDeckLauncher -ForceRestart`を削除した。
- watcherはbridge付きCodexを観測してruntimeを接続するだけのobservation-only動作へ変更した。
- bridgeなしのCodexを検出した場合は、状態をログへ記録してそのまま残す。
- 通常launcherは、bridgeなしで既存Codexが動いている場合にprocessを終了せず、明示エラーで停止する。
- `Stop-Process -Force`は、利用者が`-ForceRestart`を明示した場合だけ到達可能にした。
- 手動再起動前に、全Codex process、他タスク、未送信composer textへ影響する警告を表示する。
- macOS LaunchAgentの`restart-for-recovery`を廃止し、unbridged generationを常に観測のみとした。
- macOSのCodex終了は、利用者が手動で`--restart`を指定した場合だけ許可する。

### 3.2 安全境界

| VSD Craft plugin supervisor | 不可 | 観測のみ |

## 4. P1：CDPエラー分類

### 4.1 変更内容

`isCodexCommandRejection()`を追加し、次のcommand rejectionをtransport障害から分離した。

- command runnerが現在のbuildで見つからない。
- commandが現在のviewで非活性である。
- keycap用VS Code event module／busが現在利用できない。
- standalone keyとして未対応である。

これらの場合は理由付きエラーを呼び出し元へ返すが、CDP WebSocketを切断しない。timeout、socket close、CDP protocol errorなど既知のcommand rejectionでない失敗は、従来どおりtransportを破棄して再接続対象にする。

## 5. P1：scene描画の世代管理

### 5.1 変更内容

`RegistrationImageWriter`を追加し、物理action IDごとに次を管理する。

- register／unregisterごとのgeneration
- generation失効後の画像破棄
- 同一物理キーへの画像書き込み直列化
- 最終画像signatureによる重複書き込み抑止

旧sceneの画像取得が遅延しても、取得完了時のgenerationが現在登録と一致しなければ書き込まない。旧画像の書き込み開始後にsceneが変わった場合も、新sceneの書き込みを同じqueueの後ろへ並べ、最終状態を必ず新sceneにする。

この規則をAgent、Micro action、fixed keycap、Host、Usage Limit、Usage Overview、Rate Limit Resetへ共通適用した。

## 6. P1：危険キー3種の保護

### 6.1 対象

公式30キーのうち次の3種類を危険キーとしてコード上で一元定義した。

- `APPR`：承認待ち要求の承認
- `DEL`：現在のCodexタスクのアーカイブ
- `PLAY`：先頭Environment Actionの実行

### 6.2 入力仕様

- key-downでholdを開始する。
- 1.2秒未満のkey-upでは配送しない。
- 1.2秒以上保持した後のkey-upで1回だけ配送する。
- 二重key-upでは再配送しない。
- scene切替、キー消失、登録解除時はholdを破棄する。

### 6.3 表示仕様

- 通常keycap画像へ赤い警告枠を重ねる。
- `HOLD 1.2s`を表示する。
- 保持中は進捗バーを200ms周期で更新する。
- 閾値到達後は`RELEASE`を表示する。

Stream Deck／VSD Craft pluginとM18直接接続bindingは同じ`HoldToConfirm`と危険キー定義を使用する。

### 7.1 追加した主な回帰試験

- watcherに`RecoverExistingSession`と自動`-ForceRestart`が存在しない。
- 通常launcherが既存Codexを残し、明示的`-ForceRestart`だけが終了処理へ到達する。
- command rejectionとtimeout／socket failureを区別する。
- 遅延した旧scene画像を破棄する。
- 書き込み中にsceneが切り替わっても最終画像を新sceneにする。
- 危険キーが正確に3件である。
- 危険キー短押し0回、1.2秒長押し1回、cancel後0回である。
- 危険表示に警告枠と保持進捗が含まれる。

全件並列実行中に、`relay.test.ts`が外側の1秒timeoutへ1回だけ到達した。relay単独再試験は38/38件合格し、その後の全163件を2回連続で完走したため、機能失敗ではなく試験実行時間の一過性変動と判定した。再発時はtimeout値と並列負荷を別途見直す。
