## 2. 実装内容

### 2.1 危険キーの決定論的試験

`src/m18-action-bindings.ts`の`createM18Binding`へ、試験専用に`dangerousHoldFactory`を注入できる境界を追加した。

### 2.2 45操作dispatch matrix

`test/m18-action-matrix.test.ts`を追加し、M18の全45操作を`createM18Binding`から生成してrecording controllerへ配送した。

次を操作ごとに照合した。

- controller method
- 引数
- 呼出し回数
- key down／key upの対応
- Agent、joystick、encoder、host、Usage、reset、MIC、通常keycap
- 危険キー3種の短押し抑止と長押し単発実行

この試験は実Codex bridgeへ接続せず、稼働taskへ操作を発火しない。

### 2.3 read-only live readiness

`scripts/Test-CodexDeck-LiveReadiness.ps1`を追加した。

- buildとinstalled pluginの主要4ファイルのSHA-256比較

- 最新VSD Craft logのplugin接続確認
- M18 `willAppear` 15件以上の確認
- JSON証跡保存
- `PhysicalKeyPressesVerified=false`の明示

検査処理自体はread-onlyで、プロセスを停止・再起動しない。

## 8. 残課題と方針

1. VSD Craftが通常終了要求を受理しても終了しない原因を、VSD側log、子process、終了時hookの順に調査する。
2. P1は安全な表示・選択操作から実押下し、画面、event log、Codex側効果を同時記録する。
3. P2は非対応viewのcommand rejectionが業務エラーとして処理され、plugin接続が維持されることを確認する。
4. P3は使い捨てtaskを用意し、短押し不発、長押し単発、視覚警告を確認する。
5. P4は45操作を1件ずつ実押下し、期待結果、実結果、時刻、関連logをmatrixへ記録する。
6. `git diff --check`は本件外の動画HTML 7ファイル、9箇所のtrailing whitespaceで失敗している。merge品質Gateの前に当該所有変更と調整して解消する。
7. 物理試験用の`実機テスト実行票V1.md`と、単一起動・plugin log・VSD logを同時採取する`Capture-CodexDeck-PhysicalTestEvidence.ps1`を追加した。これにより次回は実押下だけでL2～L5の証跡を採取できる。
