# Codex Deck M18 安定化実装計画書 V6

## 1. 目的

M18直接接続経路で実害が確認されたVOICE TALKの不安定、Codex renderer/CDP評価の競合、USB/HID切断後の異常終了、無制限ログ増加、watcherの短周期再試行を、既存の`DeckController`／`CodexMicroRendererBridge`／別プロセスadapter構成を維持したまま是正する。

本計画は2026-08-29時点のリポジトリ、ローカル実ログ、Codex Desktop 26.820.10647.0に対する読み取り専用調査を根拠とする。非公開Codex内部APIを利用する性質は変えず、互換性を保証できない箇所は明示的に失敗させる。

## 2. 診断結果

### 2.1 実害が確認済み

| 重要度 | 事象 | 根拠 | 影響 |
|---|---|---|---|
| Critical | renderer評価の5秒timeoutとbridge切断 | `m18.log`に`Codex-Runtime-Antwort hat zu lange gedauert` 475件、bridge unavailable 569件。Voice押下にも切断・timeoutが対応 | Voice、Agent、Micro、keycap、snapshotの全CDP操作 |
| High | USB/HID切断時に描画Promiseがrejectし、runtimeがNode未処理例外で終了 | `HidError(Disconnected)`後に`M18 adapter is not connected`、stack trace、exit code 1を確認 | 全M18入力・LCD表示。watcher再起動まで停止 |
| High | adapter起動失敗の5秒再試行ループ | `spawn UNKNOWN` 1,231件、runtime exit 1,242件 | ログ肥大、プロセス起動負荷、原因の識別困難 |
| Medium | フレーム診断ログが無制限増加 | 6日で334,935行、56,692,062 bytes | 長期運用時のディスク消費と同期I/O負荷 |
| Medium | direct watcherログが混在encodingで破損 | PowerShell native redirect由来のNULと文字化けを実ログで確認 | 障害診断性の低下 |

VOICE固有では、物理入力は70 down／70 upで欠落がなく、短時間の再押下と`composer.startVoiceMode`の現行toggle挙動、成功確認前のpulse表示が不安定さを増幅していた。

### 2.2 再現可能な不具合

- `M18AdapterClient.command()`にはack timeoutがなく、子プロセスが生存したまま応答を失うと描画・停止処理が永久待機する。
- `Runtime.evaluate`はsnapshotと入力コマンドを同時送信でき、片方の失敗時に`disconnect()`が他方のpendingもrejectする。
- Voiceはkey-up後すぐ次のdownを受理し、開始要求をsingle-flight化していない。
- Voice pulseはコマンド結果より先に開始するため、失敗を成功のように見せる。
- `m18-events.log`と`m18-frames.log`にrotationがない。

### 2.3 高リスクな潜在不具合（今回の直接対象外を含む）

- `control-target.json`はatomic writeではなく、書込み中断時に黙ってローカルへfallbackする。
- session ownership更新は5秒ごとにsession treeを再帰走査し、環境規模によってI/O負荷が増える可能性がある。
- Codex 26.814.5167.0以降のprivate module名・command registry・React fiber構造は将来再変更され得る。
- HID切断が物理key-downとkey-upの間に起きた場合、press ownershipはruntime再起動まで残り得る。

これらは今回のログから直接の実害を確定できないか、変更範囲を広げるため、本計画の実装対象に含めない。

### 2.4 ログ上のノイズ／想定内

- relay未設定時の`remote=offline:relay-disconnected`。
- sidebarに存在しないtaskの直接選択拒否。
- VSD Craft導入時に直接接続startup shortcutが`disabled-startup`へ移動されること。
- 通常起動されたCodexをobservation-only watcherが再起動せず、bridgeなしと記録すること。

## 3. 実装対象

1. CDP `Runtime.evaluate`を直列化し、入力コマンドをsnapshotより優先する。
2. snapshot内のhashed module探索結果をrenderer lifetime内でcacheし、1.2秒ごとの全module再import・再探索を緩和する。
3. Voice開始をsingle-flight化し、短時間の重複開始を抑止する。
4. 現行Codexの開始／停止toggle化を踏まえ、既にVoice surfaceが存在する場合は開始commandを送らないstart-only相当のguardを置く。
5. Voice成功時だけpulseを表示し、失敗時は一時的なerror表示後に静止画へ戻す。
6. transport未接続時は送信前に一度だけ再接続する。実行済みか判別できないtimeout後にはtoggle commandを再送しない。
7. adapter commandにtimeoutを追加し、起動後のexit/errorをruntimeへ通知して明示的に停止し、watcher再起動へ渡す。
8. M18 event/frameログを上限付きrotationにする。
9. direct watcherにログrotation、UTF-8統一、段階的backoffを追加する。

## 4. 非対象

- VSD Craft本体、M18 firmware、USB driver、Codex Desktop設定の変更。
- relay protocol、iPhone companion、macOS launcherの仕様変更。
- private Codex API依存そのものの除去。
- `control-target.json`、session ownership全体の再設計。
- 実通話の自動開始・終了を伴うlive test。
- package dependencyの追加・version更新。

## 5. 原因と設計

### 5.1 CDP評価scheduler

汎用の優先度付き直列queueを追加する。`command`と`snapshot`の2優先度を持ち、実行中の1件を除きcommandを先に処理する。各jobは送信直前にbridge接続を再確認する。これによりsnapshot timeoutに別commandが巻き込まれる同時pending状態をなくす。

queueはtransportをpreemptしない。実行中snapshotがtimeoutするまで最大5秒待つ可能性は残るが、その後の次jobはcommandとなる。close時は未実行jobをrejectし、停止後の再接続を防ぐ。

### 5.2 snapshot cache

rendererの`Symbol.for(...)`領域へ、asset URL、exported values、settings definitions、event bus、slot resolverをcacheする。renderer reloadではglobal stateごと破棄されるため、異なるCodex buildを跨いだcache汚染は起きない。cache構築失敗時は保存しない。

### 5.3 Voice start guard

- controller／bridge双方で同一開始処理を共有し、後続tapは`suppressed`としてcommandを送らない。
- command成功後に短いsettling windowを置き、renderer側phase反映前の再押下を抑止する。
- CDP target一覧に`surfaceId=voice-*`のactive Voice composition surfaceがあれば`already-active`としてno-opにする。
- transport timeout後はcommand実行済みか判別できないため自動再送しない。
- bridge未接続の送信前だけ、schedulerが一度再接続する。

active surfaceが将来のCodexで公開されない場合はsettling guardまでが有効となる。この場合も従来より開始直後のtoggle相殺を防ぐ。

### 5.4 表示

静止VOICE TALK → command成功 → 紫pulse → 静止へ戻す。command失敗時は赤いone-shot error frameを表示し、静止へ戻す。表示失敗は元のcommand errorを隠さずloggerへ記録する。

### 5.5 adapter lifecycle

adapter childの起動後exit/errorを一度だけ通知し、controller timerとsceneを停止する。runtimeは非zero exit codeを設定し、既存watcherの再起動経路へ戻す。JSON Lines commandは既定5秒でtimeoutし、pendingを必ず解放する。

### 5.6 ログとwatcher

event/frameログは現在ファイルが上限を超えた時に`.previous`へ1世代rotationする。watcherも同様にrotationし、native command出力をUTF-8で追記する。連続失敗時は5秒から最大60秒までbackoffし、安定稼働後に戻す。

## 9. 完了条件

- Voiceの同時開始commandが最大1件である。
- Voice開始成功前に紫pulseを表示しない。
- Voice失敗が静止表示へ戻り、ログから成功と区別できる。
- active Voice surface検出時に`composer.startVoiceMode`を呼ばない。
- CDP評価が直列で、待機commandが待機snapshotより優先される。
- snapshotの全module discoveryがrenderer lifetimeで再利用される。
- adapter commandが有限時間で完了し、ready後切断がruntime停止へ伝播する。
- frame/event/watcher logが無制限増加しない。
- watcherの連続失敗が5秒固定のspawn stormにならない。
- 関連既存テストと追加テスト、TypeScript検査、対象ビルドが合格する。
- 実装報告書にlive未検証と残存private APIリスクを記録する。

## 10. ロールバック

変更はソース、テスト、文書に限定する。コミット前は対象ファイルの差分を個別に戻せる。配布物へ反映した場合は、直前releaseの`dist/m18`と`Watch-CodexDeck-M18.ps1`へ戻す。wire format・設定schema・永続化形式を変更しないため、設定migrationは不要である。

## 11. リスク

- 直列化により、実行中snapshotがtimeoutするまで入力commandが最大5秒待つ場合がある。
- CodexがVoice composition surfaceを別URLへ変更するとactive guardが効かない。その場合もsingle-flightとsettling guardは残る。
- snapshot cache対象のprivate objectが同一renderer内でhot-swapされた場合はrenderer reloadまで古くなる可能性がある。
- watcher backoffにより、長期障害後の自動復旧検出が最大60秒遅れる。
