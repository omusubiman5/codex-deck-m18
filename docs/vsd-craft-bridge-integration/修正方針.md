# 修正方針：VSD Craftへのブリッジ統合

## 調査結果

プラグインにはブリッジとPowerShell監視処理が既に同梱されている。しかし監視は観測のみで、未起動や接続口のないCodexから自力復旧しない。使用量の取得元選択も、正常な取得元がない場合に過去の値へ戻るため、古い値が残る。

## 変更

1. VSD Craft配布物に管理対象を識別するマーカーを入れ、Windows版でプラグイン所有の接続マネージャーを起動する。
2. 既存ランチャーに読み取り専用の状態取得と、VSD Craft同梱Node実行ファイルの指定を追加する。別途Nodeをインストールすることを必須にしない。
3. 起動時に一度だけ未起動Codexを自動起動する。ユーザーが後からCodexを閉じた場合は繰り返し起動しない。
4. 接続口がある場合は既存セッションを再利用し、接続失敗時は間隔を空けて復旧する。多重実行を防ぐ。
5. 全Codexボタンの設定画面に接続状態と「接続・復旧」を追加する。再起動が必要なときは同梱ヘルパーが確認を表示し、取り消しを尊重する。
6. プラグイン終了時は接続マネージャーの監視を終了する。既存の観測用watcherはrelayなどの既存役割を維持する。
7. 正常な使用量取得元がない場合は値を無効化し、キーへ未接続を表示する。正常なローカルまたはMac取得元がある場合の選択順序は維持する。
8. インストーラーから移行処理を実行する。統合パッケージの存在を確認後、旧実行ディレクトリ `launcher`・`M18`・`pending-restart` をバックアップへ移し、旧ショートカットと起動登録を撤去する。旧M18を指すVSD Craftショートカットは本体へ修正する。共有ポート情報・host/relay設定はプラグインが使うため保持する。
9. 管理対象のVSD Craftパッケージは、同梱watcherが欠けても旧外部ランチャーへフォールバックしない。

## 変更しない範囲

Codexの配布ファイル、タスクDB、起動済みCodexの無断終了、M18の割当・USB処理、ファームウェア、公開ネットワークへのCDP公開。
